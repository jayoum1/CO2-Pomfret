# Carbon DBH – Project Report (Frontend & Backend)

**Purpose:** Feed for AI-assisted planning and issue fixing. Describes structure, mechanisms, data flow, and potential issues.

---

## 1. Project overview

- **Name:** Carbon DBH (CO2 Pomfret) – forest growth and carbon sequestration simulation for Pomfret School.
- **Repo layout:**
  - **`web/`** – Next.js 14 frontend (React, TypeScript, Tailwind, Recharts).
  - **`src/`** – Python backend logic and FastAPI app (`src/api/app.py`). Run from **project root** with `python3 -m uvicorn src.api.app:app --host 0.0.0.0 --port 8000`.
  - **`Data/`** – Raw and processed CSVs, metadata (e.g. `plot_areas.json`), forest snapshots by mode.
  - **`Models/`** – Serialized models and feature lists (e.g. DBH growth, baseline bins).
  - **`app/`** – Legacy Streamlit app (optional).
  - **`R/`**, **`docs/`**, **`reports/`** – R scripts, docs, reports.

## 2. Backend (Python / FastAPI)

### 2.1 Entry and config

- **App:** `src/api/app.py` (FastAPI). Served with uvicorn from **project root** so `Path(__file__).parent.parent` is `src/`, and `parent.parent.parent` is project root.
- **Config:** `src/config.py` – paths (e.g. `PROCESSED_DATA_DIR`, `DATA_DIR`, `Models`, raw/processed CSV paths). No env-based config; paths are relative to project root.

### 2.2 Data and snapshot modes

- **Processed data:** `Data/Processed Data/` – DBH long tables, carbon tables, encoded tables, diagnostics.
- **Forest snapshots:** Precomputed CSVs per “mode” and year:
  - **baseline** → `forest_snapshots_baseline/forest_{0,5,10,20}_years.csv`
  - **baseline_stochastic** → `forest_snapshots_baseline_stochastic/`
  - **hybrid** (legacy) → `forest_snapshots_hybrid/forest_nn_{years}.csv`
  - **nn_epsilon** (legacy) → `forest_snapshots_nn_epsilon/forest_nn_{years}.csv`
- **Summary/snapshot endpoints:** Use `load_snapshot(years_ahead, mode)` with in-memory caching by `(mode, years_ahead)`. Default mode is `baseline`.

### 2.3 Main API surface

| Area | Endpoints | Purpose |
|------|-----------|--------|
| **Single tree** | `POST /predict/tree` | Next-year DBH and carbon from `api/encoding.py` (encodes user input, calls DBH growth model + forest_metrics). |
| **Snapshots** | `GET /snapshots/years`, `GET /snapshots`, `GET /summary?years_ahead=&mode=` | Years list; raw snapshot rows; summary (num_trees, mean_dbh_cm, total_carbon_kgC, plot/species breakdown). |
| **Scenario (Next.js)** | `POST /scenario/simulate` | Planting groups + mode + years_list → baseline summaries + cohort simulation → baseline_by_year, cohort_by_year, scenario_by_year, delta_by_year. Uses `simulate_cohort_forward` (baseline or baseline_stochastic or legacy hybrid/NN). |
| **Planting (recipe/explicit)** | `POST /scenarios/planting/recipe`, `POST /scenarios/planting/explicit` | Generate planting trees, run `simulate_planting_scenario` (scenarios/planting.py), return comparison. |
| **Presets** | `GET /scenarios/presets`, `GET /scenarios/presets/{filename}`, `POST /scenarios/presets/{filename}/simulate` | List/load/simulate from `Data/Scenarios/*.json`. |
| **Save scenario** | `POST /scenarios/save` | Saves to `Data/Scenarios/`. **Issue:** Endpoint takes `(scenario_config: Dict, filename: str)` as body; FastAPI treats multiple body params as separate keys, so client must send e.g. `{"scenario_config": {...}, "filename": "name.json"}`. No Pydantic wrapper documented; frontend may not call this. |
| **Area** | `GET /area/plot-areas`, `GET /area/densities?mode=`, `POST /area/scale` | Plot areas from `Data/Metadata/plot_areas.json`; densities from snapshots; scale to target area (reference: plot, Average, Range). |
| **Removal/planting bins** | `GET /removal/options`, `GET /removal/dbh-bins`, `GET /planting/dbh-bins` | Options and DBH bins for removal/planting UI. |
| **Uncertainty** | `GET /uncertainty/summary` | Reads `Data/Processed Data/diagnostics/uncertainty_summary.json`. |
| **Health** | `GET /`, `GET /health` | Info and health check. |

### 2.4 Key backend modules

- **`api/encoding.py`** – User input → feature encoding for DBH model; `predict_all_from_user_input` used by `/predict/tree`. Depends on `Models/dbh_growth_model_*.pkl` and feature list files.
- **`models/forest_snapshots_nn.py`** – `load_base_forest_df`, `simulate_forest_years`, `simulate_forest_one_year` (NN-based growth). Used by scenario/planting and by app snapshot logic for legacy modes. Baseline snapshots are generated by other pipeline (e.g. `forest_snapshots.py` / baseline simulation).
- **`models/forest_snapshots.py`** – Baseline simulation and snapshot generation (mirrors nn version with baseline growth).
- **`models/baseline_simulation.py`** – `predict_delta_sim` for baseline (and baseline_stochastic) growth; used in `simulate_cohort_forward` in app.
- **`models/dbh_residual_model.py`** – `predict_delta_hybrid` for legacy hybrid mode.
- **`models/forest_metrics.py`** – Carbon from DBH (allometry), used across app.
- **`models/area_scaling.py`** – Load snapshots by mode, compute densities, `scale_to_area`, plot summaries.
- **`models/removal_options.py`** – DBH bins and removal/planting options from snapshot data.
- **`scenarios/planting.py`** – `generate_planting_trees` (recipe/explicit), `simulate_planting_scenario`, `load_scenario`/`save_scenario` (Data/Scenarios).

### 2.5 Backend dependency gap

- **`requirements.txt`** in project root has pandas, numpy, scikit-learn, xgboost, scipy, statsmodels, matplotlib. It does **not** list **fastapi** or **uvicorn**. Docs and scripts assume `uvicorn` and FastAPI are installed. Adding them to a backend-specific requirements or the main one would avoid run failures.

## 3. Frontend (Next.js)

### 3.1 Stack and layout

- **Next.js 14**, App Router, React 18, TypeScript, Tailwind, Recharts, Radix-style UI (e.g. slider, tabs, dialog).
- **Layout:** `app/layout.tsx` → `AppShell` (header, nav, main, footer). **AppShell** (`components/layout/AppShell.tsx`) – sticky header, desktop/mobile nav, cloud decoration; no global state.
- **Routing:** Dashboard `/`, Forest Modification `/scenarios`, Generalize Area `/area`, Visualize `/visualize`, Vector Forest `/vector-forest`, R Visualizations `/visualizations`, About `/about`.

### 3.2 API client and env

- **`src/lib/api.ts`** – Single client for backend: `API_BASE_URL = process.env.NEXT_PUBLIC_API_BASE_URL || 'http://127.0.0.1:8000'`. All calls use `fetch` with JSON. Typed interfaces for Summary, ScenarioResult, PlotAreas, etc.
- **Env:** `NEXT_PUBLIC_API_BASE_URL` (default `http://127.0.0.1:8000`). Must be set for production to point at real API.

### 3.3 Page-by-page mechanisms

- **Dashboard (`app/page.tsx`)**  
  - Fetches `getAvailableYears()` then `getSummary(year, 'baseline')` for selected year and for time-series.  
  - Renders KPI cards (total carbon, mean DBH, num trees, CO₂e) and charts (Total Carbon vs Years, Carbon by Plot).  
  - **Depends on backend.** If API is down, year list or summary fails.

- **Forest Modification (`app/scenarios/page.tsx`)**  
  - Large page: removal options (plot/species → DBH bins/counts), planting (plot, species, DBH bin, count), baseline vs scenario comparison, simulation mode (baseline / baseline_stochastic).  
  - Uses `getSummary`, `simulateScenario`, `getRemovalOptions`, `getDbhBins`, `getPlantingDbhBins`.  
  - **Saved scenarios** are stored in **localStorage** only (not via `POST /scenarios/save`).  
  - **Depends on backend** for run and for removal/planting options.

- **Generalize Area (`app/area/page.tsx`)**  
  - Plot areas, target area + unit, reference (Upper/Middle/Lower/Average/Range), mode.  
  - Calls `getPlotAreas`, `getAreaDensities`, `scaleArea`.  
  - **Depends on backend** and on `Data/Metadata/plot_areas.json` (if missing, areas are null and scaling may be limited).

- **Visualize (`app/visualize/page.tsx`)**  
  - Invasive spread map (e.g. EAB): grid simulation, boundaries (Pomfret / Connecticut), presets.  
  - Uses `@/lib/geo/boundaries` and `@/lib/sim/invasiveSpread` – **client-only**, no backend.

- **Vector Forest (`app/vector-forest/page.tsx`)**  
  - Interactive “forest” of tree icons; year slider (0–30); scenario carousel (EAB, tornado, flood, fire, baseline); scenario start-year; tree inspector; pan/zoom.  
  - **Data:** Trees and growth are **fully client-side**. No snapshot or summary API calls.  
  - **Mechanism:**  
    - `VectorForestScene` generates tree list in `useMemo` from seeded RNG (count from dimensions, species keys from `TREE_SPECIES_WITH_IMAGES`).  
    - Per-tree state (DBH, carbon, alive, health, burning, charred) from `lib/vectorForest/treeModel.ts` (`getTreeState(tree, year)`) and `lib/vectorForest/scenarios.ts` (`applyScenario`).  
    - Growth formula: `dbh = clamp(dbh0 + growthRate * year, 1, 200)`; carbon placeholder: `CARBON_K * DBH^CARBON_P`.  
  - **Pan/drag:** Pointer handlers on scene root; pointer capture only after movement &gt; 6px; `lostpointercapture` and window `pointerup`/blur clear state so sliders/UI don’t block clicks.  
  - **Overlays:** Scenario visuals (tornado/flood/fire) and effect layers use `pointer-events: none`; UI (carousel, inspector, sliders) use `data-ui-overlay="true"` so pan ignores them.

- **R Visualizations (`app/visualizations/page.tsx`)**  
  - Static list of image paths: `/figures/...` and `/Graphs/EDA_Figures/...`.  
  - **Issue:** Next.js serves `public/` at root. So `/figures/...` and `/Graphs/...` require those folders under `web/public/`. If they don’t exist or are elsewhere, images 404.

- **About** – Static content.

### 3.4 Vector Forest – deeper data flow

- **Tree list:** Generated once per container size from `seededRandom(42)`; speciesKey from `TREE_SPECIES_WITH_IMAGES` for display only.  
- **State:** `getTreeState(tree, year)` → base DBH/carbon/alive; `applyScenario(config, tree, year)` applies EAB/tornado/flood/fire (health, death, burning, charred).  
- **Inspector:** Selected tree + state passed to `TreeInspectorPanel`; can “record death” (metaById) for fall direction.  
- **Stats:** Optional `onStatsChange` (baseline/scenario carbon and alive counts) for possible future UI.  
- **No backend:** Vector Forest does **not** use real baseline or hybrid snapshots; growth and carbon are placeholders. Connecting it to `/summary` or snapshot API would require design (e.g. map API trees to positions or drive a “representative” subset).

## 4. Cross-cutting and potential issues

### 4.1 Backend

1. **FastAPI/uvicorn not in requirements.txt** – Install may be missed; add or document.
2. **CORS `allow_origins=["*"]`** – Fine for dev; for production, set explicit frontend origin.
3. **`POST /scenarios/save`** – Signature `(scenario_config: Dict, filename: str)`. Clients must send a single JSON body with both keys; no request model documented. Scenarios page saves only to localStorage and does not call this endpoint.
4. **Snapshot path consistency** – `GET /snapshots` hardcodes `forest_snapshots_nn_epsilon`; other endpoints use `mode` and cached `load_snapshot`. If frontend ever calls `/snapshots` without a mode, it’s tied to nn_epsilon only.
5. **Data/Scenarios and Data/Metadata** – Presets and area scaling depend on `Data/Scenarios/*.json` and `Data/Metadata/plot_areas.json`. Missing or invalid files cause 404 or empty/fallback behavior.
6. **Run from project root** – All path logic assumes CWD or paths relative to project root. Running uvicorn from another directory can break data/model paths.

### 4.2 Frontend

1. **No API fallback** – Dashboard, Scenarios, Area show errors if backend is unreachable; no offline or graceful degradation.
2. **Saved scenarios** – Stored only in localStorage; not synced to backend or `POST /scenarios/save`. Clearing storage loses them.
3. **R Visualizations** – Image paths assume `public/figures/` and `public/Graphs/` (or equivalent). Wrong paths or missing build-time copy will 404.
4. **Vector Forest vs real data** – Tree growth and carbon are client-side mocks. Any “later hook to real baseline” (as in page comment) would require API integration and mapping strategy.
5. **Duplicate min-height** – `vector-forest/page.tsx` container has both `min-h-0` and `min-h-[500px]`; one overrides the other; harmless but redundant.

### 4.3 Vector Forest – recent fix

- **Pointer capture / clicks:** Previously, pan logic called `setPointerCapture` on pointerdown, which could steal all pointer events after slider use. Fix: capture only after movement &gt; 6px; clear state on pointerup, pointercancel, lostpointercapture, and on window blur/pointerup (when target outside scene). Overlays and UI use `pointer-events: none` or `data-ui-overlay="true"` so pan doesn’t start on sliders/trees. If click bugs reappear, check that no new overlay has `pointer-events: auto` over the whole viewport and that capture is still deferred and cleaned up.

### 4.4 Data and file assumptions

- **Baseline snapshots** – Must exist for years 0, 5, 10, 20 (and optionally others) in the mode used by the frontend (e.g. baseline). Missing files → 404 from `/summary` or snapshot endpoints.
- **Plot areas** – If `plot_areas.json` is missing or has null areas, “Average” or single-plot scaling can fail or be incomplete.
- **Species and bins** – Removal/planting options depend on snapshot and model data; wrong or missing data can yield empty options or wrong counts.

## 6. Suggested next steps for planning

1. Add **fastapi** and **uvicorn** to requirements (or a dedicated backend requirements file) and document run-from-root.
2. Define a **single Pydantic request model** for `POST /scenarios/save` and, if desired, implement “Save to server” in Scenarios page using it.
3. Either **copy or symlink** R/EDA figures into `web/public/` and align paths in `/visualizations`, or change the page to use asset paths that already exist in `public/`.
4. Decide whether Vector Forest should stay mock-only or **integrate real snapshots/summaries** (e.g. one tree set per snapshot, or aggregate stats only) and document the contract.
5. Add **health check or connectivity check** on frontend (e.g. on Dashboard load) and show a clear “Backend unavailable” state instead of generic fetch errors.
6. **Tighten CORS** and set **NEXT_PUBLIC_API_BASE_URL** for production.
